# Amni-Code web UI (Helium)

The page logic is Helium, written in Gold (`*.gold` → `*.he`, each with its `.gold.lock`). `static/index.html` holds markup and CSS only. The browser loads `static/start.js`, which applies the saved skin before first paint and starts `static/ui.wasm` through the Helium web host `static/helium.js`.

## Build

```
export HC_LIB=<helium>/hc/lib GOLD_HC_LIB=<helium>/hc/lib GOLD_HC=<hc>
gold pack core <repo>/ui skip='^(app|chat|settings|look|editor|panes|picker)\.he$'
gold pack md <repo>/ui skip='^(app|core|chat|settings|look|editor|panes|picker)\.he$'
cd ui && gold build <module>.gold
$GOLD_HC build --web app.he -o ../static/ui.wasm
```

The UI needs a Helium `hc/lib` with streaming fetch (`web::stream`, `EV_CHUNK`, `web::fetch_abort`), which is on helium `main`. The `gold pack` lines run once: feature modules name `use core` and `use md` in their Gold headers, and Gold resolves those as packs. `app.gold` and `editor.gold` import the modules through an `he` fence instead.

`hc build --web` also writes `helium.js` beside the wasm. `static/start.js`, `static/helium.js` and `static/ui.wasm` are committed and embedded by `src/main.rs`, so `cargo build` does not need the Helium toolchain.

## Tests

- `tests/e2e/offline_e2e.sh target/debug/amni`: two agent turns against local stub servers in a loopback-only network namespace, then `tests/e2e/ui_click.js` clicks through skin, tone, settings, language, history, editor, palette, quick open, panes and shortcuts. Both fail on any page error or non-loopback request.
- `ui/test/md_oracle.mjs` + `md_run.he`: byte-for-byte markdown parity (1940 cases) against the original JS renderer, read from the pre-port commit `a4487952872e`.
- `ui/test/settings_run.mjs`, `picker_smoke.mjs`, `look_panes_smoke.mjs`, `chat_smoke.mjs`, `editor_driver.mjs editor_cases.mjs`: per-module headless runs against stub servers.
- `tests/test_*.py`: source checks on the markup, `ui/data/*.json` and the generated Helium.

## Module contract

Every feature module exposes exactly:

- `init()`: called once by `main` in the order core, look, settings, chat, editor, panes, picker. It registers its own listeners (`web::listen`) with tags from its own hundred and starts its first fetches.
- `event(tag i32, kind i32)`: called by the root for every tag in the module's hundred, with the host's event kind (`web::EV_DOM`, `EV_TIMER`, `EV_FETCH`, `EV_CHUNK`, `EV_JS`, `EV_CALLBACK`).
- `act(verb const byte[:], arg const byte[:])`: called by the root for every queued action named `<module>.<verb>`. The element that triggered it, when there is one, is `core::act_el`.

Feature modules never call each other. They call only `core::`, `md::` and the standard library (`web`, `json`, ...). To ask another module for something, a module queues an action with `core::post("editor.toggle", "")`. The root drains the queue after every event.

Markup triggers actions without JS: a click anywhere inside an element with `data-act="chat.undo"` queues that action with the element's `data-arg` (empty when absent) and the element as `core::act_el`. A `change` event on an element with `data-change="settings.save"` queues that action with the element's current `value` as the argument. HTML that a module generates uses the same attributes instead of inline handlers.

## What stays JavaScript

- `static/helium.js`: the Helium web host (DOM, fetch and timer bridge), generated by `hc`.
- `static/start.js`: applies the saved skin attributes before first paint, then starts the wasm.
- `static/vendor/monaco`: the Monaco editor, a third-party library driven from `editor.he` through `web::js_call`.
- `ui/test/*.mjs`, `tests/e2e/*.js`: test harnesses (the original-JS oracle and the headless browser runs).
